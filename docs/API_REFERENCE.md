## Overview

The **Mellow Café System** uses Next.js 15 **Server Actions** (`'use server'`) for all data mutations and queries. All server actions authenticate the requesting user via `@/lib/supabase/server` (`getAuthenticatedUser()`) and leverage Supabase Row-Level Security.

## Module 1: Inventory Server Actions

Source: `src/app/(dashboard)/inventory/actions.ts`

### 1. `getProducts()`
Fetches all products owned by the authenticated user sorted alphabetically by name.

- **Parameters:** None
- **Returns:** `Promise<{ data: Product[] | null; error: string | null }>`
- **Errors:** Returns `{ data: null, error: 'Unauthorized' }` if unauthenticated or Supabase error message if query fails.

---

### 2. `getProductsByCategory(category: string)`
Fetches products filtered by a specific category.

- **Parameters:**
  - `category` (`string`): Category name or `'All'` to return all products.
- **Returns:** `Promise<{ data: Product[] | null; error: string | null }>`

---

### 3. `createProduct(formData: FormData)`
Creates a new product record. Automatically calculates `unit_cost` if package costing details (`package_price` and `items_per_package`) are provided.

- **Validation Schema:** `createProductSchema` (Zod)
  - `name`: string, min 1 char
  - `category`: string, min 1 char
  - `selling_price`: number >= 0
  - `unit_cost`: number >= 0
  - `current_stock`: integer
  - `low_stock_threshold`: integer >= 0
  - `target_stock`: integer >= 0
  - `package_price`: optional number >= 0
  - `items_per_package`: optional integer >= 1
  - `package_unit_name`: optional string
- **Business Rule:**
  $$\text{unit\_cost} = \frac{\text{package\_price}}{\text{items\_per\_package}}$$
- **Returns:** `Promise<{ success: boolean; error: string | null }>`
- **Side Effects:** Revalidates `/inventory` cache path.

---

### 4. `updateProduct(formData: FormData)`
Updates an existing product record.

- **Validation Schema:** `updateProductSchema` (Zod)
- **Returns:** `Promise<{ success: boolean; error: string | null }>`
- **Side Effects:** Revalidates `/inventory` cache path.

---

### 5. `deleteProduct(id: string)`
Deletes a product by ID.

- **Parameters:** `id` (`string`)
- **Returns:** `Promise<{ success: boolean; error: string | null }>`
- **Error Handlers:**
  - FK Constraint check: If product is referenced in `sales_items`, returns error `"Cannot delete product that has existing sales records."`
- **Side Effects:** Revalidates `/inventory` cache path.

---

### 6. `addStock(productId, quantity, isPackage, updatePackagePrice, newPackagePrice)`
Adds stock to a product in individual pieces or bulk packages.

- **Parameters:**
  - `productId` (`string`): Target product ID.
  - `quantity` (`number`): Quantity to add.
  - `isPackage` (`boolean`): If `true`, quantity is treated as packages and multiplied by `items_per_package`.
  - `updatePackagePrice` (`boolean`): Optional toggle to update default package price.
  - `newPackagePrice` (`number`): Optional new package price.
- **Business Rule:**
  $$\text{Added Pieces} = \begin{cases} \text{quantity} \times \text{items\_per\_package} & \text{if } \text{isPackage} = \text{true} \\ \text{quantity} & \text{otherwise} \end{cases}$$
- **Returns:** `Promise<{ success: boolean; error: string | null }>`
- **Side Effects:** Revalidates `/inventory` path.

## Module 2: Sales Server Actions

Source: `src/app/(dashboard)/sales/actions.ts`

### 1. `recordQuickTapSale(data: unknown)`
Records a real-time sale made via POS Quick Tap mode.

- **Validation Schema:** `quickTapSaleSchema`
- **Calculation Logic:**
  - $\text{totalRevenue} = \sum (\text{qty} \times \text{unitPrice})$
  - $\text{totalCogs} = \sum (\text{qty} \times \text{unitCost})$
  - $\text{netProfit} = \text{totalRevenue} - \text{totalCogs}$
- **Stock Decrement:** Decrements product `current_stock`. Emits warnings if stock goes negative, but transaction is allowed to proceed.
- **Returns:** `Promise<{ success: boolean; saleId?: string; warnings?: string[]; error?: string }>`
- **Side Effects:** Revalidates `/sales`, `/inventory`, and `/dashboard` paths.

---

### 2. `recordBatchSale(data: unknown)`
Records aggregated end-of-day sales in bulk.

- **Validation Schema:** `batchSaleSchema`
- **Returns:** `Promise<{ success: boolean; saleId?: string; warnings?: string[]; error?: string }>`

---

### 3. `recordReconciliation(data: unknown)`
Records daily cash register closing and calculates cash overage/shortage.

- **Validation Schema:** `reconciliationSchema`
  - `startingFloat`: number >= 0
  - `endingCash`: number >= 0
- **Calculation Logic:**
  $$\text{expectedCash} = \text{startingFloat} + \text{todayCashSales}$$
  $$\text{cashDiscrepancy} = \text{endingCash} - \text{expectedCash}$$
- **Returns:** `Promise<{ success: boolean; expectedCash?: number; cashDiscrepancy?: number; todayCashSales?: number; error?: string }>`

---

### 4. `getTodaysSummary()`
Aggregates sales performance metrics for the current day.

- **Returns:** `Promise<{ data: DailySummary | null; error: string | null }>`
- **DailySummary Properties:**
  - `totalRevenue`: Sum of revenue (excluding `reconciliation` records).
  - `totalCogs`: Sum of COGS.
  - `netProfit`: Revenue minus COGS.
  - `totalItemsSold`: Quantity count.
  - `totalCashSales`: Cash payment totals.
  - `transactionCount`: Number of sales transactions.
